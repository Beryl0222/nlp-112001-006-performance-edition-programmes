# 双卡司节目册的演出版本校对

剧场排演备忘采用 UTF-8 编码，人物、单位和记录均为合成内容。

| 资料 | 字段 |
| --- | --- |
| `资料/卡司表.json` | `id`、`performance`、`act`、`role`、`performer`、`stageName`、`locale` |
| `资料/排演札记.json` | `id`、`date`、`authority`、`text` |
| `资料/连场文案.json` | `id`、`language`、`context`、`text` |
| `资料/版次.json`（可选） | `id`、`title`、`kind`、`scope`、`copyIds`、`castCells`、`deliveredAt`、`issuedAt`、`revision`、`erratumFor`、`translationReview` |

每份资料是 JSON 数组。记录中的字段值按来源原样保留为字符串，逗号和顿号可以属于字段内容。资料中可能有转述、不同的拼写以及较晚录入的更正。数字及日期在这些文件中沿用各资料自身的含义；原文位置以记录编号及文本范围定位。

Node.js 22 环境下运行以下命令可安装锁定的项目环境、检查素材格式并读取各类资料的数量。

```sh
npm ci --offline --ignore-scripts --no-audit --no-fund
npm test
npm run materials
```

`readMaterials` 只读取资料，不解析其中的正文含义。

## 校对命令

```sh
npm run audit                                  # 完整校对报告
npm run ticket -- 河剧十九日晚                  # 票面场次对应哪些版本
npm run ticket -- 河剧十九日晚 -- --at 2026-10-19T19:30:00+08:00
node audit.js --json                           # 结构化结果
```

报告分四部分：

- **名册与拼写**：官方写法、艺名；同一艺名对应多位演员时列出全部候选与卡司表依据。
- **各场次适用版**：逐场逐幕的当前安排、依据的记录与原文范围、跨幕是否同一人、未确认或冲突。
- **文案校对**：每句中英文字对哪些场次成立、哪些必须替换、哪些待核实；译审是否需要重签。
- **版次与生效范围**：未付印稿、电子页、已送达纸本、勘误各自的生效范围；互相引用的页面如何成组替换；已演场次可还原为当时文字。

## 判定规则

- 只更换部分幕/部分场次时，其它幕与其它场次保留原安排；“第一幕照旧”不会把上一句的演员带过来。
- “次日”“本幕”等省略按同一条札记内上文补全；补不出时记为错误，不作猜测。
- 同一艺名对应多人时保留候选，不替编辑择一；只有当班安排能唯一确定时才取定，并留下提示。
- 首演经历、替补/备用名单、合排名单、以往巡演都不能用来确认当晚人选。
- 一个页面只有在文案与所印署名对**每一场**都成立时才能共用；只要一场不成立，其它干净场次仍可单页沿用。
- 晚到译审的签样只对签样时的署名有效，换角后自动失效。
- 勘误只覆盖它写明的场次和幕；未覆盖的幕仍取原纸本，已演场次的还原不受影响。
